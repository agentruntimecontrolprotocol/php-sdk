## 1. `docs/` tree

`docs/{architecture,cli,conformance,getting-started,recipes,transports,troubleshooting}.md`).

Departures from the TS shape, justified:

- **`concepts/`** — TS has `guides/{sessions,jobs,leases,…}.md`; PHP
  splits "what is a session on the wire" (concept) from "how to use
  the PHP API to drive it" (guide). The `Session` value object is
  immutable post-welcome (Phase 04 §5), so the concept page is short
  and stable while the guide grows when the public API does.
- **`reference/capabilities.md`** — TS doesn't have one. PHP needs it
  because the `Arcp\Session\Feature` enum (Phase 01 §3.1) is closed
  by design and any downstream consumer of the SDK needs to know
  which values they can `match` against without grepping source.
- **`guides/deployment.md`** — TS doesn't need it; Node servers are
  always long-lived. PHP **MUST** document the daemon-not-`php-fpm`
  constraint (Phase 02 §7) because the default PHP deployment shape
  (request-per-fork) is incompatible with the heartbeat loop (§6.4),
  the ack buffer (§6.5), and the `job.subscribe` listener (§7.6).
- **`guides/{psr-15-host,laravel,symfony}.md`** — TS ships
  `packages/{express,fastify,hono,bun,node}.md` against one runtime.
  PHP has multiple host idioms and the middleware adapter strategy
  is Phase 05's; each guide lives next to the package it consumes.
- **TS-only pages dropped:** `docs/packages/{bun,hono}.md` (no
  equivalent PHP host); `docs/typescript-types.md`-style pages (not
  applicable — phpDocumentor renders types from source).
- **`docs/api/`** — generated. Not authored. See §3 below.

The index page `docs/README.md` mirrors `../typescript-sdk/docs/README.md`
section-for-section: "Start here" / "Concepts (one per spec section)" /
"Guides" / "Packages" / "Reference". A two-column linkable table per
section keeps the same density.

## 2. Frontmatter convention

Every authored `docs/*.md` opens with YAML frontmatter. The shared
docs site reads it; GitHub renders it as-is in the file head.

```yaml
---
title: Sessions
sdk: php
spec_sections: [§6.4, §6.5]
order: 10
kind: concept
---
```

Fields and rules:

- `title` — string. Renders as `<title>` and `<h1>`. The first `#`
  heading in the body is dropped to avoid duplication; the renderer
  injects from frontmatter. Keep the in-body `#` as well for raw-MD
  readers — Phase 09 diagrams sit under it.
- `sdk: php` — literal. Lets the cross-SDK index filter by language.
- `spec_sections` — list of strings, each a `§N.M` form. Required on
  every page that documents a wire surface; omit only on pages that
  are pure PHP idiom (`guides/laravel.md` may set `[]`).
- `order` — integer. Sort key inside its directory; 10/20/30/… so
  insertions don't renumber.
- `kind` — one of `concept`, `guide`, `reference`. The labels match
  the directory: `docs/concepts/*` is `concept`, `docs/guides/*` is
  `guide`, `docs/reference/*` is `reference`. Top-level files
  (`getting-started.md`, `architecture.md`, etc.) declare explicitly.

Per-file kind:

| File                                  | kind        |
| ------------------------------------- | ----------- |
| `docs/README.md`                      | (no frontmatter; index)  |
| `docs/getting-started.md`             | guide       |
| `docs/architecture.md`                | concept     |
| `docs/transports.md`                  | concept     |
| `docs/cli.md`                         | reference   |
| `docs/recipes.md`                     | guide       |
| `docs/troubleshooting.md`             | reference   |
| `docs/concepts/*.md`                  | concept     |
| `docs/guides/*.md`                    | guide       |
| `docs/reference/*.md`                 | reference   |

Pages that contain a `<picture>` referencing a Phase 09 diagram cite
it under the H1; pages that don't, don't fabricate one.

## 3. phpDocumentor

Every public method on the public-API classes in Phase 04 §5
(`Arcp\Client\ArcpClient`, `Arcp\Runtime\Server`, `Arcp\Transport\Transport`,
the value objects in `Arcp\Session`, `Arcp\Job`, `Arcp\Lease`) carries:

- `@param <type> $<name>` for every parameter, including narrowed
  `array{…}` shapes where the param is `array` (e.g. `array<string, mixed>`
  for `$input` on `submitJob`).
- `@return <type>` including generic seam types — `Amp\Future<\Arcp\Job\Job>`,
  `Amp\Pipeline\Pipeline<\Arcp\Job\Event\JobEvent>`.
- `@throws Arcp\Errors\<Name>Exception` for every wire-error class
  the method can surface, **one line per code**. The full set is
  the 15 from Phase 01 §1 / Phase 04 §4.1:
  `InvalidRequestException`, `UnauthenticatedException`,
  `PermissionDeniedException`, `JobNotFoundException`,
  `AgentNotAvailableException`, `AgentVersionNotAvailableException`,
  `CancelledException`, `TimeoutException`, `InternalErrorException`,
  `LeaseSubsetViolationException`, `LeaseExpiredException`,
  `BudgetExhaustedException`, `ResumeWindowExpiredException`,
  `HeartbeatLostException`, `DuplicateKeyException`.
- `@throws Arcp\Errors\UnnegotiatedFeatureException` on every method
  gated by a `Feature` (Phase 01 §3.4) — library-internal, but
  surfaced so consumers can `catch` it during integration tests.

Internal classes (`Arcp\Runtime\JobManager`, `Arcp\Runtime\LeaseManager`,
`Arcp\Store\EventLog`) carry phpDocumentor blocks for cross-package
clarity but are excluded from the rendered output (see config below).

### 3.1. Generator config

phpDocumentor v3 (PHP 8.3 compatible; v2 is dead). Config file
`phpdoc.dist.xml` at repo root:

```xml
<phpdocumentor configVersion="3">
  <paths><output>docs/api</output></paths>
  <version number="1.1.0">
    <api>
      <source dsn="."><path>src</path></source>
      <ignore><path>src/Cli/**</path></ignore>     <!-- moves to arcp/cli -->
      <ignore><path>src/Internal/**</path></ignore><!-- if introduced -->
      <output>docs/api</output>
      <visibility>public</visibility>
      <markers><marker>TODO</marker></markers>
    </api>
  </version>
</phpdocumentor>
```

`visibility=public` excludes `protected`/`private` from the rendered
HTML. The internal classes still get their docblocks (PHPStan reads
them); they just don't appear in `docs/api/`.

### 3.2. Composer wiring

```jsonc
{
  "require-dev": {
    "phpdocumentor/shim": "^3.5"
  },
  "scripts": {
    "api-docs": "phpdoc --config=phpdoc.dist.xml"
  }
}
```

**Why `phpdocumentor/shim` over `phpdocumentor/phpdocumentor`:** the
unshimmed package pulls in the full phpDocumentor application
(symfony components, twig, …) and **conflicts** with consumer deps in
practice — it's the reason most modern PHP projects use the shim or
the PHAR. The shim is a thin Composer entry that delegates to the
official PHAR at install time; runtime deps stay clean. The package
is `require-dev` — phpDocumentor is a build tool, not a runtime
concern, and bringing it into `require` would break Phase 02's
"justify every dep" rule (Phase 03 §0 floor).

`composer api-docs` is invoked from CI on the release branch; the
rendered tree is published to the docs site, not committed.

### 4.3. Quickstart code-block rule

Every code block in the README — and in every page under `docs/` —
must run as written. The reader copy-pastes, runs `php file.php`,

## 6. `MIGRATION-v1.1.md`

New file under `docs/`. One-page migration note for consumers of
the current v0.1 / RFC-0001 SDK. Bullet list; no marketing; cites
Phase 02 §6 for the full re-baseline list.

Outline:

```yaml
---
title: Migration to v1.1
sdk: php
spec_sections: [§5, §6, §7, §8, §12]
order: 1
kind: guide
---
```

```
# Migration to v1.1

## Wire shape (Phase 02 §6)

- Envelope literal `arcp: "1"` is now required (§5.1).
- `session.open` / `session.accepted` / `session.authenticate` /
  `session.challenge` are gone. Single handshake:
  `session.hello` → `session.welcome` (or `session.error`).
- `session.close` / `session.evicted` → `session.bye`.
- `job.started` is gone. Submission is `job.submit` → `job.accepted`.
- Top-level `log` / `metric` / `event.emit` / `tool.invoke` /
  `tool.result` / `tool.error` / `stream.chunk` envelopes are gone.
  Everything an agent emits flows as `job.event { kind, body }`
  with one of nine kinds (§8.2 + §8.2.1 progress + §8.4
  result_chunk).
- Lease lifecycle envelopes (`lease.granted` / `lease.refresh` /
  `lease.extended` / `lease.revoked`) are gone. Leases are immutable
  per job; replace with a fresh `job.submit` carrying a new
  `lease_request` (§9).

## Namespace moves (Phase 04 §1.1)

- `Arcp\Json\EnvelopeSerializer` → `Arcp\Envelope\EnvelopeSerializer`.
- `Arcp\Client\ARCPClient` → `Arcp\Client\ArcpClient` (note casing).
- `Arcp\Runtime\ARCPRuntime` → `Arcp\Runtime\Server`.
- `Arcp\Cli\*` moves out of core into the `arcp/cli` package.
- `Arcp\Auth\JwtAuth` moves out of core into the `arcp/auth-jwt`
  package; `Arcp\Auth\BearerAuth` becomes
  `Arcp\Auth\StaticBearerVerifier`.

## API rename (Phase 04 §5)

- `registerTool($name, ToolHandler)` → `registerAgent($name,
  AgentHandler, versions: [...], default_version: ...)`.
- `invokeTool($name, $args)` is gone. Use
  `submitJob(agent: $name, input: $args, …)` returning
  `Future<Job>`; await `Job::done()` for the terminal result.
- `JobContext::openStream()` is gone. Emit events via
  `JobContext::event(Kind::*, $body)`.

## Error classes retired (Phase 04 §4.2)

- Retire `AbortedException`, `DataLossException`,
  `FailedPreconditionException`, `UnavailableException`,
  `UnimplementedException`, `OutOfRangeException`,
  `ResourceExhaustedException`, `AlreadyExistsException`,
  `DeadlineExceededException`. None map to spec §12.
- Keep `ArcpException`. Rename `NotFoundException` →
  `JobNotFoundException`.
- New: `AgentVersionNotAvailableException`, `LeaseExpiredException`,
  `BudgetExhaustedException` (Phase 01 §2).

## Dependency drops (Phase 02 §6 + Phase 03)

- `justinrainbow/json-schema` removed (typed decoders suffice).
- `symfony/console` removed from core (lives in `arcp/cli`).
- `firebase/php-jwt` removed from core (lives in `arcp/auth-jwt`).
- `ext-json` declaration removed (bundled in 8.x).
- `ext-pdo_sqlite` moves from `require` to `suggest`.

## Runtime constraint (Phase 02 §7)

The v1.0 + v1.1 runtime needs heartbeat (§6.4) and ack-buffer
(§6.5) loops that outlive a single HTTP request. Host the runtime
under `systemd` / `supervisord` / `amphp/cluster` / Docker — not
under `php-fpm`. The client is unaffected; submit jobs from a
normal `php-fpm` worker.
```

One page. No code. Consumers who want code see `docs/guides/quickstart.md`.

## 8. Voice rules

- Terse. Sentences average under 20 words. No "in order to" — use
  "to". No "simply" — if a step is simple, the reader will see.
- No marketing. No "blazing", "buttery", "delightful", "first-class
  developer experience".
- **Banned words** (per BOOTSTRAP anti-slop): "leverage", "robust",
  "scalable", "performant", "powerful", "modern" (used as filler),
  "enterprise-grade", "elegant". Greppable in CI: a `composer
  docs-lint` script (Phase 07 if it fits) runs
  `grep -niE '\\b(leverage|robust|scalable|performant|powerful|modern|enterprise-grade|elegant)\\b' docs/ README.md`
  and fails on a hit. The grep tolerates `modern` only when adjacent
  to a specific PHP feature name on the same line.
- **No emojis** anywhere in `docs/`, `README.md`, `CHANGELOG.md`,
  `CONFORMANCE.md`, `MIGRATION-v1.1.md`, or phpDocumentor output.
